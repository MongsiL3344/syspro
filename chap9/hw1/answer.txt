과제1 – 전면처리, 후면처리 실습

1. sleep 100 &
출력 결과
[1] 5197

설명
명령 끝에 &를 붙이면 해당 명령은 백그라운드에서 실행됨
전면 실행일 경우 sleep이 끝날떄까지 기다려서 100초가 소요되지만
백그라운드 명령의 경우에는 자식 프로세스의 종료를 기다리지않기 때문에 실행 결과가 바로 반환됨
[작업번호] PID 의 형태로 출력 

2. sleep 100 &
출력결과 
[1]+  Done                    sleep 100
[1] 5234

설명
첫번쨰줄은 아까 실행한 명령이 100초가 지나서 완료되었다는 기록
두번쨰줄은 이번에 다시 실행한 백그라운드 명령의 작업번호와 PID
기존 작업이 먼저 끝난 상태에서 다시 백그라운드 작업을 등록했으므로 작업번호는 다시 1부터 시작

3. jobs
출력결과 (sleep 100 &를 3번 더 실행하고 확인했습니다)
[1]   Running                 sleep 100 &
[2]-  Running                 sleep 100 &
[3]+  Running                 sleep 100 &
jobs는 현재 쉘이 관리하고 있는 백그라운드 작업(및 정지된 작업)의 목록을 보여주는 쉘 내장 명령
실행중인 작업은 Running으로 나오고 +는 가장 최근 작업, -는 그 직전 작업을 의미함

4. ps -f
출력결과
UID          PID    PPID  C STIME TTY          TIME CMD
wkdgust+    5027    5026  0 15:25 pts/1    00:00:04 -bash
wkdgust+    5408    5027  0 15:32 pts/1    00:00:00 sleep 100
wkdgust+    5445    5027  0 15:32 pts/1    00:00:00 sleep 100
wkdgust+    5511    5027  0 15:34 pts/1    00:00:00 ps -f

설명
ps -f는 현재 터미널에서 실행중인 프로세스들을 자세하게 보여줌
순서대로 프로세스 소유자, 프로세스id, 부모프로세스id, cpu사용량, 프로세스 시작시간, 연결된 터미널, 사용한 cpu시간, 실행한 명령을 표시한다

5. kill %1
출력결과
[1]   Terminated              sleep 100

설명
kill은 프로세스에 종료 시그널을 보내는 명령어
%작업번호 인자를 통해 대상을 지정할 수 있음
kill %1은 작업번호 1번 프로세스에 종료 시그널을 보냄

6. ps -f
출력결과
UID          PID    PPID  C STIME TTY          TIME CMD
wkdgust+    5027    5026  0 15:25 pts/1    00:00:05 -bash
wkdgust+    5621    5027  0 15:36 pts/1    00:00:00 sleep 100
wkdgust+    5640    5027  0 15:36 pts/1    00:00:00 sleep 100
wkdgust+    5740    5027  0 15:38 pts/1    00:00:00 ps -f

설명
kill %1로 첫번쨰 sleep 프로세스가 종료되어서 목록에서 사라짐
ps -f는 실행할떄마다 새로운 프로세스로 만들어져 
아까 5번에서 보았던 ps -f의 PID와 이번 실행의 PID가 달라짐
